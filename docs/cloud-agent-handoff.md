# Cloud Agent Handoff

## What Is Cloud Agent Handoff?

**Cloud agent handoff** is a mechanism in GitHub Copilot's agent mode that allows an AI agent session to gracefully transfer its working context to a new session when the current one is approaching its token or context limits.

When an agent session runs long — for example, during a complex multi-file refactor or an extended debugging session — it will eventually hit the model's context window limit. Rather than losing all of that accumulated understanding, the agent:

1. **Generates a structured summary** of everything that has been accomplished so far, decisions made, files changed, and what still needs to be done.
2. **Packages that summary into a handoff document** (sometimes called a "continuation prompt" or "agent summary"), which captures:
   - The original objective
   - The current state of the codebase or task
   - Completed work
   - Pending tasks and their priorities
   - Any relevant context (error messages, tool results, partial code, etc.)
3. **Passes the handoff document to a new agent session**, which picks up exactly where the previous session left off — without losing the thread.

In essence, it is the AI equivalent of a shift handoff in engineering teams: a structured, written summary that lets the next person (or agent) continue seamlessly.

## Why Does It Matter for This Project?

When using GitHub Copilot agent mode to work on this extension, long sessions (such as large refactors, building features across multiple files, or debugging complex rendering issues) can exhaust the model's context window. Cloud agent handoff ensures that work-in-progress is never silently dropped — the agent documents what it knows and hands it forward.

The problem statement that triggered this document is itself an example of a cloud agent handoff: a previous Copilot agent session hit its token budget while answering questions, and it produced a structured summary so the next session could continue.

## Can the Agent Access Code from a Live Website?

Yes — within limits. GitHub Copilot's agent mode can use tools to fetch content from URLs. Specifically:

- **Public web pages and documentation**: The agent can retrieve content from publicly accessible URLs (HTML, plain text, JSON, etc.) using web fetch tools.
- **GitHub repositories**: The agent has native access to GitHub APIs and can read files, commits, issues, and pull requests from any public (or authorized private) repository.
- **Raw file URLs**: Direct links to raw source files (e.g., `raw.githubusercontent.com`) are fetchable.

**What the agent cannot do:**

- Access pages that require authentication or are behind a login wall (unless credentials are explicitly provided and the tool supports it).
- Execute JavaScript in a live browser to scrape dynamically rendered content — it reads the raw HTTP response, not the DOM after JS runs (unless a browser tool is specifically enabled).
- Access private/internal URLs that are not reachable from the agent's sandboxed environment.

For this extension specifically, if you want the agent to review code from a live website or external repository, share the URL directly in your message and the agent will attempt to fetch and analyze it.

## Summary

| Concept | Description |
|---|---|
| **Cloud agent handoff** | Structured context transfer between AI agent sessions when token limits are reached |
| **Handoff document** | A summary of completed work, current state, and pending tasks generated by the outgoing session |
| **Website code access** | Agent can fetch public URLs, GitHub repos, and raw files; cannot access auth-gated or JS-rendered content |
